Sentinel学习

2026-02-20 微服务学习 Sentinel 评论

Sentinel 学习与使用文档

本文档从背景、作用、使用方式与业务场景等方面介绍阿里巴巴开源的 Sentinel，便于系统学习与落地使用。

一、背景

1.1 微服务下的稳定性问题

随着架构从单体拆成微服务，系统会面临：

  • 流量不可控：大促、爬虫、恶意刷接口导致 QPS 暴增，下游或本机被打挂。
  • 依赖故障扩散：某个下游服务变慢或宕机，调用方线程被占满、超时堆积，最终整条调用链雪崩。
  • 资源争抢：少数热点 key 或慢 SQL 占满连接/线程，影响其他请求。

若没有统一的「流量与稳定性」治理手段，只能靠人工扩容、重启或下线，无法在运行时按规则自动限流、熔断与降级。

1.2 Sentinel 的由来

  • Sentinel 是阿里巴巴开源的面向分布式服务架构的流量治理与熔断降级组件，前身经历过多年双十一等大促验证。
  • 与 Hystrix 等相比，Sentinel 以资源为核心，支持限流、熔断、系统保护、热点与授权等多种规则，并提供实时监控与控制台，规则可动态配置、即时生效。
  • 在 Spring Cloud 体系中常与 Spring Cloud Alibaba 一起使用，对 Web、Feign、Dubbo 等都有适配。

1.3 为什么需要「资源」与「规则」分离

  • 业务代码只声明哪些是受保护的资源（一个 URL、一个方法、一次 RPC 等）。
  • 限流/熔断的阈值、策略放在控制台或配置中心，可随时调整，无需改代码、重启。
  • 这样既保证运行时可控，又便于按环境（开发/预发/生产）区分策略。

二、作用概览

Sentinel 主要解决以下几类问题，对应不同「规则」与「使用方式」。

能力 解决的问题 典型场景
限流 流量超过承载能力导致服务不可用 接口 QPS/并发控制、防刷、秒杀
熔断降级 下游异常/慢调用导致雪崩 Feign 调用、DB/Redis、慢方法
系统保护 CPU、负载、入口 QPS 等系统级过载 根据系统水位自动拒绝部分请求
热点参数 少数参数（如某个 userId）占满资源 热点 key、大促热点商品
授权/黑白名单 只允许/禁止特定来源访问某资源 内部接口只允许网关或特定服务

日常使用最多的是 限流 和 熔断降级，下文重点介绍这两部分的概念与使用方式。

三、核心概念（必知）

3.1 资源（Resource）

  • 资源是 Sentinel 里被保护的最小单位，可以是：
    • 一个 URL（如 Web 适配器自动为每个请求生成的 GET:/api/xxx）
    • 一个方法上的 @SentinelResource(value = "xxx")
    • 一段代码里的 SphU.entry("xxx")
  • 所有限流、熔断等规则都是按「资源名」配置的，控制台里看到的「簇点链路」就是已出现过的资源。

3.2 入口（Entry）与上下文（Context）

  • 每次请求会有一个 Context，其中第一次 entry(资源名) 对应的资源称为该请求的入口。
  • 链路流控依赖「入口」：同一资源从不同入口进来，可以配置不同的限流阈值（例如普通入口 10 QPS，VIP 入口 2 QPS）。
  • 若 Web 适配器先对 URL 做了 entry，则入口往往是 URL 资源，而不是你在代码里再写的 entrance_xxx，配置链路规则时需注意「入口资源」要填控制台里实际看到的第一个资源。

3.3 限流（Flow Control）与熔断（Circuit Breaking）

  • 限流：当某个资源的 QPS 或并发线程数超过规则阈值时，立即拒绝（或排队/预热），不执行业务逻辑，返回 block 结果。
  • 熔断：当某个资源的异常比例、慢调用比例或异常数超过规则阈值时，Sentinel 会在一段时间内认为该资源不可用，这段时间内请求不再进入该资源，直接走 block（降级），避免继续打挂下游；过了熔断时长后会进入「半开」试探是否恢复。

3.4 blockHandler 与 fallback

  • blockHandler：被限流或熔断时调用（对应 BlockException），用于返回「请求被拒绝/服务降级」等统一结果。
  • fallback：方法内部抛业务异常时调用，用于返回兜底结果或错误信息；若希望「异常也参与熔断统计」，应在方法里抛异常，由 fallback 做降级返回。

四、限流：概念与使用

4.1 限流相关概念

  • QPS 限流：每秒允许通过该资源的请求数上限，超过则拒绝（或按流控效果排队/预热）。
  • 并发线程数限流：同时执行该资源的线程数上限，超过则拒绝，适合保护「慢接口」不被太多线程占满。
  • 流控模式：
    • 直接：只针对当前资源本身做阈值判断。
    • 关联：当「关联资源」的 QPS 达到阈值时，限制当前资源（例如写接口受读接口流量影响）。
    • 链路：根据「入口资源」区分，同一资源从不同入口进来可设不同阈值（需 web-context-unify=false，且入口为实际第一个 entry 的资源名）。
  • 流控效果：
    • 快速失败：超限直接拒绝。
    • Warm Up：从较小阈值逐渐升到设定 QPS，避免冷启动被打满。
    • 排队等待：超限请求排队，在超时时间内等待，适合允许一定延迟的场景。

4.2 使用方式一：@SentinelResource（推荐用于「一个方法一个资源」）

  • 在控制台为资源 example_api 配置流控规则（QPS 或并发数）即可生效。
  • 限流/熔断时走 blockHandler，方法抛异常时走 fallback。

4.3 使用方式二：SphU.entry（适合细粒度、多资源）

  • 必须在 finally 中调用 entry.exit()，否则统计与限流会异常。
  • 同一方法内可多次 SphU.entry("不同资源名")，实现对不同代码段分别限流。

4.4 业务场景示例

场景 建议做法
普通 HTTP 接口 用 @SentinelResource 标注方法，控制台按 QPS/并发设阈值。
秒杀/活动接口 QPS 限流 + Warm Up 或排队等待，避免瞬时打满。
写接口受读接口影响 写接口资源使用「关联」模式，关联到读接口资源。
同一逻辑多入口不同限制 使用链路流控：入口为 URL 或显式 SphU.entry("entrance_xxx")，控制台按入口资源配置不同 QPS。
热点参数（如某 userId） 使用「热点规则」对参数维度限流。

五、熔断降级：概念与使用

5.1 熔断相关概念

  • 熔断：当资源在统计窗口内满足「异常比例 / 慢调用比例 / 异常数」等条件时，Sentinel 将该资源置为熔断状态，在熔断时长内不再放行请求到真实逻辑，直接走 block（降级）。
  • 熔断策略（三选一）：
    • 慢调用比例：响应时间超过「最大 RT」的请求占比超过「比例阈值」则熔断（如 50% 请求 > 500ms 则熔断）。
    • 异常比例：统计窗口内异常请求占比超过「比例阈值」则熔断。
    • 异常数：统计窗口内异常数量达到「异常数阈值」则熔断。
  • 最小请求数：统计窗口内请求数达到该值后才参与判断，避免样本过少误熔断。
  • 熔断时长：熔断状态持续时间，结束后进入半开，再根据后续请求是否正常决定恢复或再次熔断。

5.2 使用方式（与限流共用同一套资源定义）

熔断不改变「资源」的写法，只是多了一类「熔断规则」：

  • 仍用 @SentinelResource(value = "xxx", blockHandler = "xxx", fallback = "xxx") 或 SphU.entry("xxx") 定义资源。
  • 在控制台为该资源配置熔断规则（异常比例/慢调用比例/异常数 + 阈值、熔断时长、最小请求数）。
  • 熔断打开时，请求不会进入方法体，直接触发 blockHandler，因此 blockHandler 里应返回「服务降级」类结果（如 503、默认数据）。

5.3 业务场景示例

场景 建议做法
Feign 调下游服务 为 Feign 接口配置 fallback/fallbackFactory，控制台对 Feign 资源名配置熔断规则（异常比例或慢调用比例）。
调 DB / Redis / MQ 对「调用 DB/Redis 的那段逻辑」作为资源，配置熔断 + fallback 返回默认值或友好提示。
第三方 HTTP 接口 同 Feign：资源为「调用该接口的方法」，熔断 + blockHandler 返回降级结果。
本机内易出错或耗时的逻辑 用 @SentinelResource 包住该方法，配置熔断；异常由 fallback 处理，熔断打开时由 blockHandler 返回降级。

5.4 与 Feign 结合说明

  • Feign 调用是熔断的典型场景：下游超时或异常时，通过熔断快速失败并走 fallback，避免线程堆积和雪崩。
  • 使用方式：开启 spring.cloud.openfeign.sentinel.enabled=true，为 Feign 接口指定 fallback 或 fallbackFactory；控制台中对 Feign 自动暴露的资源名（一般为 接口全限定名#方法名）配置熔断规则即可。
  • 注意：在 Spring Boot 4 + Jackson 3 环境下，若开启 Feign Sentinel 报错，可补充 com.fasterxml.jackson.core:jackson-core（2.x）依赖或暂时关闭 Feign Sentinel，仅对「本机内模拟下游」的资源的熔断做演示（逻辑一致）。

六、控制台与配置要点

6.1 控制台（Dashboard）

  • 用于查看实时监控（通过 QPS、拒绝 QPS、响应时间）、簇点链路（资源列表）、流控规则 / 熔断规则等。
  • 规则在控制台配置后会推送到应用，应用内规则变更可实时生效（无需重启）。
  • 应用要出现在控制台，需：
    • 引入 spring-cloud-starter-alibaba-sentinel（或至少 sentinel-transport-simple-http）；
    • 配置 spring.cloud.sentinel.transport.dashboard、transport.port 等；
    • 应用启动后至少有一次请求触发该资源，或开启 eager=true 等以便尽早注册。

6.2 常用配置项（application.properties / yaml）

配置项 说明
spring.cloud.sentinel.transport.dashboard 控制台地址（如 localhost:8080）
spring.cloud.sentinel.transport.port 本机暴露给控制台的端口（默认 8719）
spring.cloud.sentinel.transport.client-ip 本机 IP，控制台连回应用时使用
spring.cloud.sentinel.eager true 时启动即初始化并连接控制台
spring.cloud.sentinel.web-context-unify false 时按请求区分入口，链路流控才可能按「入口」生效

七、小结

  • 背景：微服务下流量与依赖故障带来的稳定性问题，需要统一的限流与熔断能力；Sentinel 以「资源 + 规则」的方式提供这些能力。
  • 作用：限流（控 QPS/并发）、熔断降级（异常/慢调用时快速失败）、系统保护、热点与授权等；最常用的是限流和熔断。
  • 使用：
    • 限流：用 @SentinelResource 或 SphU.entry 定义资源，在控制台配置流控规则（直接/关联/链路 + QPS 或并发 + 流控效果）。
    • 熔断：同一资源在控制台配置熔断规则（异常比例/慢调用比例/异常数），熔断期间走 blockHandler 降级。
  • 业务场景：普通接口限流、秒杀/活动、Feign 调用熔断、DB/Redis/第三方调用熔断、热点参数限流等，均可通过「资源 + 对应规则」实现。
